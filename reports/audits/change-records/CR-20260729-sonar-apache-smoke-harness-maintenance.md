## Motivation and problem statement

The Apache smoke harness repeated fixed protocol, curl-format, response-marker,
transport-result, and configuration-terminator values at multiple call sites.
Four branch-local success messages also went to standard output although they
are diagnostics rather than machine-readable result payloads. This caused the
current SonarQube Cloud maintainability findings.

## Acceptance criteria

- Each of the six fixed values named by current `shelldre:S1192` findings has
  one readonly Shell owner, and all operational uses preserve prior bytes and
  command arguments.
- The four `shelldre:S7677` Phase-4 success diagnostics write to stderr while
  preserving their text, branch selection, and zero exit status.
- Phase-4 marker controls remain present and fail closed; no rule, test,
  scanner, or quality control is weakened.
- Focused shell and Parent contract validation passes with generated bytecode
  and temporary files outside the source checkout.

## Implementation decision and rationale

The harness now owns the affected values in readonly variables:
`PHASE4_RESPONSE_BODY_MARKER`, `APACHE_LOCATION_END`,
`HTTP2_PROTOCOL_LABEL`, `CURL_H2_ALPN_ACCEPT_PATTERN`,
`CURL_HTTP_STATUS_FORMAT`, and `OBSERVED_TRANSPORT_HTTP_STATUS`. Curl, grep,
expected-body, generated-configuration, and evidence-writing sites consume
those values without changing their output.

The Phase-4 regression contract now protects marker ownership directly: the
marker appears once in the readonly declaration, expected bodies compose the
same bytes, and marker searches remain through the readonly variable. The four
pass diagnostics use `>&2`; their messages and control flow are unchanged.
