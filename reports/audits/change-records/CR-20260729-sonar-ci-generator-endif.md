## Motivation and problem statement

The connector-neutral block-status generator emits the same C preprocessor end
token in the extern-C closure, C++ guard closure, and include-guard closure.
SonarQube Cloud reports that repeated generated-output literal as `python:S1192`.

## Implementation decision and rationale

`PREPROCESSOR_ENDIF = "#endif"` now supplies those three unchanged positions.
The status allowlist, connector allowlist, numeric parsing, deterministic sort,
CLI parameters, output locations, and generated text order remain unchanged.

## Acceptance criteria

- Only the three equivalent generated-header end-token references change.
- Existing generated output is byte-for-byte equivalent for representative
  empty, normal, reordered, and full-allowlist status selections.
- All supported connectors and the invalid duplicate/range/unsupported/
  non-integer/unknown-connector cases retain their existing outcome.
- A future exact PR head must receive zero new SonarQube Cloud issues and
  `0.0%` New-Code duplication without weakening rules or controls.

globally allowlisted HTTP statuses influence those outputs. The constant is an

source-to-sink path, validation, branch, destination, or generated byte.

this narrow literal refactor neither broadens nor mitigates it. No security
finding is claimed, suppressed, or closed by this record.
