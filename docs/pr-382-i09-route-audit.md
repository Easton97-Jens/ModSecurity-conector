## Operation-specific contract

The native connection, URI, header-add, phase-processing, file-body and logging APIs require exactly `1`. Memory body append accepts `0` or `1`; EOS phase processing still requires `1`. Intervention accepts `0` or `1`, and Common/HAProxy keep nondisruptive intervention `1` as allow. Negative and undocumented positive returns are technical failures. Checked Common transaction/session/host-action APIs return `1` on success and `0` on failure. Native error classification survives a NULL optional error-output pointer.

Native invalid results become `invalid_engine_response`; host/API fallback becomes `connector_error`. Protocol, timeout, unavailable engine, client cancellation and upstream disconnect retain distinct causes. The first canonical cause and `error_phase` survive later callbacks, finish and cleanup. Technical events carry status `error`, empty rule ID and no actual action before observed host effect. BODY_LIMIT stays `body_limit`/`blocked`; a genuine rule decision, including rule status 500, stays distinct. Requested action expresses policy, not observed enforcement. Failed phases cannot complete successfully or reenter native processing; cleanup/logging and terminal emission have once-only guards.
