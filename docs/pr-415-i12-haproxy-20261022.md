A green SPOP request ACK contributes no companion qualification by itself.

Accepted Safe response packets contain physical MRC1 `CLAIM→HEADERS→COMMIT→BODY→EOS→OUTCOME→RELEASE`, native P1–P4, physical Common event output, native audit A/Z, one Finish/Free and actual client `200`. Precommit P3 cases are evaluated against their disruptive OUTCOME→RELEASE order and absence of a committed response; no EOS is invented for those branches.

Streaming and payload-end-marker runs observe a positive `SSL_write` before P4. The shorter Safe charset/CSV/client-exit/backend-count cases observe the host commit boundary before P4, with the positive `SSL_write` after P4. The [phase contract](../common/docs/transaction-phase-contract.md) permits the first successful next-stage write or host commit as the boundary. Those short cases therefore do not claim client bytes before P4.

The parallel neighboring-stream run remains `PARTIAL`: 16 main requests produce ten backend/MRC/client `200` results and six client `502` results, with seven unknown observation fields. It receives no lifecycle credit.

Allow and response-empty cases remain partial because the terminal physical Common response event is missing. Safe/Strict 33-byte probes remain partial at the complete-lifecycle layer. Strict now produces actual EOF with zero client bytes in the retained probe, but missing physical P4 Common/OUTCOME and terminal correlation evidence prevents qualification. Missing/wrong/stale OUTCOME and missing-EOS cases retain negative or partial dispositions; missing/expired correlation and the earliest technical cause must be established from physical events.
