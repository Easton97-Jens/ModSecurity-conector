## Frozen evidence selection

The selection contains **21 expanded main cases**, below the shared ceiling of
100. The one shared budget covers Common, every connector and logical profile,
unit/integration/runtime cases, harness/validator/evidence infrastructure, and
Parent-selected Framework/MRTS cases. These 21 consume that shared budget;
there is no separate I12, PR, runner, job, agent, or language allowance. The
selection is deliberately smaller than the ceiling and covers all 13 required
logical profiles. Cases were selected from the existing Root-reviewed lifecycle
ledger for distinct EOS, request/response chunking, content-type, native
Reject/ProcessPartial, association/lease, response-companion, and empty-body
behavior. Neighboring controls and packet observations are evidence for their
main case; they were not scheduled as new cases.

Every row records its stable ID and requirement, connector/profile, evidence
layer, actual result, Parent/product/Framework/MRTS revisions, host/build
identity, configuration and rules hashes, run ID/date, packet path, packet hash,
and scope limits. All 21 results are historical `PASS` at the
`full_host_lifecycle` layer on 2026-10-14. Their Parent revisions are
`02754040...`, `3a1bafec...`, or `8cc32dce...`, not the current PR heads.
Therefore current PR #382 and #410 applicability is **`not_verified`** for every
selected case.

This frozen evidence selection is not an executable default-suite inventory.
Current Makefile and CI paths still invoke tests directly; no authoritative
project-wide active inventory or pre-execution expanded-count guard was found.
Automatic technical enforcement of the 100-case cap is therefore
**`not_verified`** and remains a separately scoped migration.
